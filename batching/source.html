    v0.11.0 · EngineCore.step Scheduler.schedule 结果更新与结束 Chunked prefill
    • 静态侧为算法教学模型：AB 开批后锁定成员，不等满 3 个请求；整批结束后再开 CD。完成行释放 KV，空位不补。未统计 padding 或已结束行的无效计算。
    • 静态侧也可逐 token 输出；准入规则与是否流式输出是两回事。这里不把静态批处理画成 vLLM V1 的实现分支。
    • 到达时机按各侧轮次设置，用于解释调度机制，不是同一真实时间到达流的性能测试。4 轮对 6 轮不等于具体加速比。
    • V1 同步主路径；FCFS、普通文本生成、全注意力；无前缀复用、抢占、推测解码或流水线并行。
    • A / C 生成 3 个 token，B / D 生成 2 个 token 后停止；无提前 EOS。输入及输出均为教学符号。
    • 开启 chunked prefill；本例提示词都能放入剩余预算，没有实际切块。P / D 是教学标签，V1 按待计算 token 统一调度。
    • KV 数表示已有 KV 的 token 数；实际显存按块分配。刚采样的 token 在下一轮作为输入时才写入自己的 KV。
    • 图中的计划箭头传递调度元数据；GPU 使用本地 KV，没有在每轮传输整个 KV cache。名额与 KV 不足时，新请求仍需等待。
