调用链范围 · vLLM 295c062db8 · 同步 MRV1

固定同步 Scheduler、ModelRunner V1、batch_queue=None，单一 FullAttention KV group、关闭前缀缓存且无外部 KV connector，以本页两个教学算例走一轮或两轮。异步调度与 step_with_batch_queue() 不在此树内。

编号保持稳定；缩进表示调用或明确标记的控制块。「动作」是函数内部语句，「循环」「分支」是控制流。省略诊断日志、统计等辅助路径；执行器内部的 Worker、RPC、模型 forward 留在边界外。

调用关系来自本地源码静态核对，token、容量与模型返回是教学取值。页面可离线查看，源码链接需要网络；可视化展示状态快照，不会启动推理。

      SOURCE NOTES

      对照源码

      队列里的请求去了哪里？
      跨轮保留的请求
      self.running 存放已准入请求。等待侧先取持有 KV 块的 self.kv_holding_waiting，再取普通 self.waiting。self.deferred_waiting 是标记阻塞或暂跳请求的集合。请求本身在等待队列中，扫描时也可能在本轮暂跳 deque 中等待回填。成员定义
      每次调用新建的四张清单
      续算成功进入 scheduled_running_reqs。从等待队列准入时，按原状态 WAITING / PREEMPTED 分别进入 scheduled_new_reqs / scheduled_resumed_reqs，随后改为 RUNNING。受害请求记入 preempted_reqs 并回到普通等待队列。
      Worker 收到哪些数据
      MRV1 将首次准入编码为 NewRequestData，将续算与恢复合并为 CachedRequestData，用 resumed_req_ids 标出恢复者。MRV2 把恢复者并入新请求格式。输出中的 preempted_req_ids 取自跨调用累计的 self.reset_preempted_req_ids。输出打包
      如何从请求长度算出这一轮的 token 数？
      RUNNING 的进度缺口
      num_tokens 含提示和已追加的输出，num_tokens_with_spec 再加候选草稿。初始 num_new_tokens = num_tokens_with_spec + num_output_placeholders − num_computed_tokens。异步输出占位代表尚待回填的位置。按有效的长提示阈值、双预算及 max_model_len − num_computed_tokens − num_sampled_tokens_per_step 截断。RUNNING 公式
      WAITING 的可复用前缀
      进度为零时查询前缀，将本地 num_new_local_computed_tokens 与额外的 num_external_computed_tokens 相加。若需重放前缀尾部，再减去重放量。已有进度直接沿用。普通准入取 num_new_tokens = num_tokens − 有效前缀进度，所以恢复请求也会计入历史输出。异步拉取 KV 时先分配块，本轮新算量为零。WAITING 公式
      两本预算与一个请求名额
      token_budget 起于 max_num_scheduled_tokens，input_budget 起于 max_num_batched_tokens。本请求最多可排 min(token_budget, input_budget − draft_slots)。若 n = 2 且 draft_slots = 2，成功后分别扣 2 和 4。准入另查 len(running) + num_waiting_for_streaming_input 是否达到 max_num_active_reqs，这里数的是请求。
      本轮计划与模型回报
      分配成功才写 num_scheduled_tokens[id] = n，所有请求求和得到 total_num_scheduled_tokens。构造输出后、返回前，请求的 num_computed_tokens 和 num_in_flight_tokens 各加 n。模型结果返回后扣除在途量，拒绝的草稿可回滚进度。num_output_tokens 数的是已经追加到请求的输出 token。进度更新
      跳过、停止扫描和抢占，下一步分别到哪里？
      跳过并继续扫描
      RUNNING 本次可算量为零时，留在原列表并继续看下一项。等待者若仍在编译语法等，skip_request() 暂存到 step_skipped_waiting 或 step_skipped_kv_holding，扫描结束后按持块情况回填。它们对应流程里的“跳过”分支。等待队列扫描
      退出本阶段
      等待侧请求名额已满、输入位置不足，或队首 KV 分配失败时，结束等待扫描。已经排定的请求仍会进入本轮输出。
      抢占并等待后续轮次恢复
      RUNNING 分配失败且可即时释放时选取受害者。FCFS 取队尾，priority 策略取优先级最低者。若后者本轮已记账，撤销分配记录并退还双预算。释放请求的块、清零计算进度，令 num_preemptions += 1。本轮发生抢占就跳过整个等待阶段，恢复最早在后续轮次发生。抢占与回滚
