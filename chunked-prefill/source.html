Chunked prefill

教学实例：A 提示词 18 tokens；B / C 从已生成的 b0 / c0 继续 decode
A 的 prefill decode 输入 每轮输入预算 ≤ 8 tokens 右列：每轮结束后的 A 输出
示例条件与源码对应
初始
B / C 已在 RUNNING，最新输出为 b0 / c0，尚未作为模型输入处理；K_B / K_C 是此前已有 KV，不含 b0 / c0。
模型
普通自回归文本生成、全因果注意力、单 GPU 示意；无前缀命中、无推测解码、无抢占，KV 容量充足。
分块
v0.11.0 / V1：输入预算 8；无额外长 prefill 阈值。RUNNING 顺序 B → C → A，因此每轮留给 A 6 tokens。
不分块
v0.6.6 / V0 历史 prefill-first 策略：预算 32，max_model_len = 32。A 的 18 tokens 一次进入，B / C 等待；调度 1 内分三个观察点，调度 2 才执行 Decode。不是将 18 tokens 分成三次各 6，也不是仅切换同一 V1 配置开关。
可比性
两项均用 A 的 18-token prompt 与 B / C 的 Decode。版本、调度策略与预算不同，不是同一 V1 开关的性能对比。整段侧的三个观察点属于同一次调度，不表示固定耗时或 token 处理速率。
饥饿
整段侧调度 1 中 B / C 停在 b0 / c0，KV 不增长；A 完成后，调度 2 才恢复。持续到来的高优先级 prefill 还可能延长等待。
计数
V1 的 num_computed_tokens 在安排后预先推进；图中 KV 只在执行步骤后增长。采样产生的 token 到下一次作为输入执行时才有自己的 KV。
缓存
条带表示逻辑 token 的 KV，不表示物理 block 大小。各请求 KV 独立；后续 EOS / 长度上限结束时释放请求占用。
验证
源码语义与页面交互检查；数值为教学示例，未运行模型或硬件测速。
