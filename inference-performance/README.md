# 推理性能基础

打开 `index.html`。三个场景覆盖双请求流式时间线、单 token 输出的边界，以及单个 GEMM 的计算/传输下界；每个场景有七步输入、计算和结果消费流程。

默认时间戳：A 在 0 ms 提交，输出 `[100,110,120,135]`；B 在 20 ms 提交，输出 `[110,120,130,150]`。TTFT 为 100/90 ms，TPOT 为 35/3 与 40/3 ms。共同窗口为 150 ms，8 个输出 token 对应约 53.3333 tokens/s。每事件一个 token，E2E 截止最后输出；单 token 的 TPOT 标为不适用。

GEMM 场景用 `2MKN` 计 FLOPs，`(MK+KN+MN)×2` 计一次读写的字节数。算力与带宽都是可修改的假设值；两项耗时取最大值是理想重叠下界，不是实测延迟。不能用单个矩阵乘代替完整模型，也不声称 Decode 必然受带宽限制。

本页属于基础知识，不伪造框架调用链。依据为页面列出的 vLLM benchmark 指标文档和 NVIDIA 性能背景文档。编辑 `lesson.js` 后运行仓库三项页面生成器。独立验算：`node inference-performance/verify.mjs`。
