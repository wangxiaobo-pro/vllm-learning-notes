完整编号流程

    等待、中断与缓存分支
    预算 / 块不足
    新请求留在 WAITING → 后续轮次重试步骤 6；已有请求可被抢占，释放占用并回等待队列，之后重算或命中缓存。
    分块 Prefill
    步骤 6–10 可分多轮处理 prompt；中间轮不向客户端输出有效 token，完成 prompt 的那一轮才产生 t1。
    前缀命中
    步骤 6 复用已缓存完整块，减少待算 token；本例无命中。每次 Decode 先用已有块，空间耗尽才需要新块。
    EOS / token stop
    Scheduler 可提前判停 → 步骤 18；本例假设无提前停止，输出 3 个 token 后以 length 结束。
    字符串 stop
    前端 OutputProcessor 识别 → 结束前端输出并反向 ABORT → Scheduler 清理；与本例的长度终止路径不同。
    客户端断连
    generate 被取消 → 前端清理并发送 ABORT → Scheduler 移出队列、释放引用 → Worker 后续清理。
    适用范围与源码依据
    模型权重与 GPU KV 池已在启动阶段准备好。示例为纯文本、decoder-only full attention、单请求展示，token 预算足够；无投机解码、无 PD 分离。p/t、R1、B7 与 16 槽均为教学标识，不是实测输出。
    编号是一种合法交错顺序；前端发送与引擎后续计算可重叠。步骤 19 与 20 都依赖 18，彼此没有固定先后。SSE chunk、文本片段与 token 不保证一一对应。
